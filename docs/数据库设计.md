# 数据库设计文档

> B 负责维护。建表 SQL 在 `schema.sql` 文件中。

## ER 关系概览

```
users (用户)
  │
  ├── farms (农场) ── fields (地块) ── crops (作物)
  │                                      │
  │                    ┌─────────────────┼─────────────────┐
  │                    │                 │                 │
  │              observations      diagnosis_records   farming_tasks
  │              (观察记录)         (诊断记录)          (农事任务)
  │                    │                 │
  │                    └───────── agent_runs (Agent执行记录)
  │
  ├── weather_records (天气记录)
  ├── market_prices (市场价格)
  ├── knowledge_documents (知识文档)
  └── model_versions (模型版本)
```

## 核心表设计

## 索引建议

```sql
-- 高频查询字段建议加索引
CREATE INDEX idx_fields_farm ON fields(farm_id);
CREATE INDEX idx_crops_field ON crops(field_id);
CREATE INDEX idx_diagnosis_field ON diagnosis_records(field_id);
CREATE INDEX idx_diagnosis_status ON diagnosis_records(status);
CREATE INDEX idx_diagnosis_crop ON diagnosis_records(crop_id);
CREATE INDEX idx_tasks_field ON farming_tasks(field_id);
CREATE INDEX idx_tasks_status ON farming_tasks(status);
CREATE INDEX idx_tasks_due ON farming_tasks(due_date);
CREATE INDEX idx_weather_loc_date ON weather_records(location, record_date);
CREATE INDEX idx_market_crop_date ON market_prices(crop_type, record_date);
CREATE INDEX idx_observations_field ON observations(field_id);
CREATE INDEX idx_agent_diagnosis ON agent_runs(diagnosis_id);
```

## 数据规范

- **所有图片存 MinIO，数据库只存 URL**
- **密码用 BCrypt 加密存储，绝不存明文**
- **诊断结果用 JSON 字段存储，方便 AI 输出格式变化**
- **所有表都有 created_at 和 updated_at（除纯记录表外）**
- **软删除用 status 字段标记，不真删数据**

## 种子数据

初始化时插入：
- 4个测试用户（每种角色一个）
- 30条农技知识文档（番茄病害、辣椒病害、花卉病害各10条）
- 最近7天的天气数据（昆明呈贡）
- 最近30天的市场价格（番茄、辣椒）
- 一个示例农场 + 3个地块 + 当前在种的作物
